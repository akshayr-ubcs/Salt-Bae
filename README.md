# SaltBae

**SaltBae is a sensor-guided, machine-learning-assisted salt-dosing
prototype.** It measures ice thickness with an ultrasonic sensor,
combines that measurement with pavement-temperature and humidity inputs,
predicts a salt dose, and controls a servo-operated gate to dispense
salt.

The project explores a more measured approach to winter de-icing: apply
salt according to the observed conditions rather than relying only on a
fixed dose. The prototype is intended for controlled demonstrations and
experimentation. It is **not a validated road-treatment system**.

## How it works

1.  An HC-SR04 ultrasonic sensor measures the distance from the sensor
    to the test deck.
2.  Arduino firmware takes five readings, uses the median of valid
    readings, and estimates ice thickness from a configured empty-deck
    baseline.
3.  The Arduino exposes sensor and dispensing functions through
    `Arduino_RouterBridge`.
4.  A Python Flask application polls the Arduino, reads the current
    temperature and humidity settings, and predicts the salt
    requirement.
5.  Python converts the predicted grams into a servo gate-open duration
    using a configured demo flow rate.
6.  The Arduino opens the gate for the requested duration and then
    closes it.
7.  The web dashboard displays readings and predictions and can save
    observed outcomes to a CSV file for future model training.

``` text
HC-SR04 sensor
     |
     v
Arduino UNO Q / RouterBridge <------ Servo-controlled salt gate
     |
     | Bridge calls
     v
Python Flask application
     |
     +---- Temperature and humidity inputs (dashboard sliders)
     |
     +---- Trained regression model (.joblib)
     |
     +---- Predicted salt dose -> gate-open duration
     |
     +---- Dashboard / telemetry / CSV sample logging
```

## Hardware

### Components represented in the firmware

-   Arduino UNO Q with `Arduino_RouterBridge`
-   HC-SR04 ultrasonic distance sensor
-   Servo motor attached to the salt gate
-   A test deck / platform used as the empty-surface reference
-   A salt container and gate mechanism

### Pin connections

  Component        Arduino pin
  -------------- -------------
  HC-SR04 TRIG               8
  HC-SR04 ECHO               7
  Servo signal               9

Use an appropriate power supply and common ground for the sensor and
servo. Check the electrical requirements of the specific board, sensor,
and servo before wiring; do not assume the board can safely power a
high-current servo directly.

### Sensor and gate settings in `sketch_latest.ino`

  -------------------------------------------------------------------------
  Setting                              Current value Meaning
  --------------------- ---------------------------- ----------------------
  `DECK_BASELINE_MM`                          150 mm Measured
                                                     sensor-to-empty-deck
                                                     distance

  `NOISE_FLOOR_MM`                              3 mm Estimated thickness at
                                                     or below this value is
                                                     treated as noise / no
                                                     ice

  `MAX_OPEN_MS`                             5,000 ms Firmware maximum
                                                     gate-open duration

  Valid distance                     At least 3 of 5 Minimum valid
  readings                                           ultrasonic readings
                                                     required for a
                                                     thickness estimate
  -------------------------------------------------------------------------

The firmware estimates thickness as:

``` text
ice_thickness_mm = DECK_BASELINE_MM - median_distance_mm
```

The median of up to five valid distance readings is used to reduce the
effect of outliers. If fewer than three readings are valid, the function
reports `0 mm` ice and sets the raw distance to `-1`.

**Important:** `DECK_BASELINE_MM` must match the actual measured
distance from the installed sensor to the empty deck. Recalibrate it if
the physical geometry changes.

## Machine-learning model

The training script implements a **supervised regression** task.

### Inputs and output

  Type      Column                  Unit
  --------- ----------------------- -------
  Feature   `ice_thickness_mm`      mm
  Feature   `pavement_temp_c`       °C
  Feature   `humidity_pct`          \%
  Target    `required_salt_grams`   grams

The script supports two training modes.

### 1. Synthetic training data (default)

Run the script without arguments to generate 20,000 synthetic samples
using the hand-designed `needed_salt_grams()` formula.

-   60% of ice samples are drawn from 0--15 mm.
-   40% are drawn from 15--40 mm.
-   Temperature is sampled from -15°C to 2°C.
-   Humidity is sampled from 40% to 100%.
-   Gaussian noise with standard deviation 0.3 g is added to the
    formula-generated target.
-   Negative target values are clipped to zero.

**Synthetic-data limitation:** the model learns to approximate the
formula used to generate its labels. Good test metrics on this dataset
do not establish real-world salt-dose accuracy. Real measurements are
needed to assess whether the predictions work under actual conditions.

### 2. Real measurement data

The training script accepts a CSV containing these exact columns:

``` text
ice_thickness_mm,pavement_temp_c,humidity_pct,required_salt_grams
```

Rows with missing values in the required columns are dropped. The script
warns if fewer than 200 usable rows are available; this is a warning,
not a guarantee that 200 rows are sufficient.

The dashboard can log observations to `data/samples.csv`. The user
enters the amount of salt that actually cleared the ice. Review and
validate these labels before using them as training targets. The logged
values are human-entered observations, not automatically verified ground
truth.

### Model selection and evaluation

The training script compares:

-   `RandomForestRegressor` --- 60 trees, maximum depth 14, minimum 20
    samples per leaf.
-   `HistGradientBoostingRegressor` --- up to 800 iterations, learning
    rate 0.05, maximum 63 leaf nodes, minimum 10 samples per leaf.

The dataset is split into 80% training and 20% held-out testing. The two
candidate algorithms are compared using five-fold cross-validation on
the training portion, using RMSE (lower is better). The candidate with
the lower mean cross-validation RMSE is fitted on the training portion
and evaluated on the held-out test portion.

Reported metrics:

-   **R²:** goodness-of-fit measure.
-   **RMSE:** root mean squared prediction error, in grams.
-   **MAE:** mean absolute prediction error, in grams.

The selected model is saved as `saltbae_rf_model.joblib`.

## Software setup

The Python application imports:

-   Flask
-   pandas
-   joblib
-   `arduino.app_utils.Bridge`

The training script additionally imports:

-   NumPy
-   scikit-learn

Install the standard Python packages in the Python environment used for
training:

``` bash
python -m pip install flask pandas numpy scikit-learn joblib
```

The `arduino.app_utils.Bridge` module is provided by the Arduino UNO Q /
Arduino App Lab runtime. Run the Flask application in the supported
Arduino environment where that module and the RouterBridge connection
are available.

Use compatible versions of scikit-learn when training and loading the
`.joblib` model. The training script prints the scikit-learn version
used; keep that version aligned in the runtime environment.

## Train the model

From the project root (the directory where you want
`saltbae_rf_model.joblib` to be created):

``` bash
python train_salt_model_new.py
```

This creates:

``` text
saltbae_rf_model.joblib
```

To train from collected measurements instead:

``` bash
python train_salt_model_new.py --data data/samples.csv
```

The CSV must contain the four required columns listed above. The
training script writes the model to its current working directory, so
run it from the project root if that is where `main.py` expects the
model.

## Run the application

1.  Upload `sketch_latest.ino` to the Arduino UNO Q using the supported
    Arduino development workflow.
2.  Confirm the sensor and servo wiring and verify the empty-deck
    baseline.
3.  Ensure `saltbae_rf_model.joblib` is in the project root. If it is
    absent, `main.py` falls back to the hand-written formula for
    predictions.
4.  Run `main.py` from the Arduino UNO Q application environment, where
    `arduino.app_utils.Bridge` is available.
5.  Open the Flask dashboard on port `5000` from a browser that can
    reach the board.

The Flask server is configured with:

``` text
host: 0.0.0.0
port: 5000
```

The exact launch/deployment command depends on how the project is
configured in Arduino App Lab.

## Dispensing logic

In `main.py`, the predicted dose is converted to a gate duration using:

``` text
duration_seconds = predicted_salt_grams / FLOW_RATE_G_PER_SEC
duration_ms = duration_seconds * 1000
```

Current Python settings:

  Setting                                                          Value
  ------------------------------------------------ ---------------------
  `FLOW_RATE_G_PER_SEC`                                           15 g/s
  `MIN_OPEN_MS`                                                   400 ms
  `MAX_OPEN_MS`                                                 5,000 ms
  Autonomous polling interval                                0.4 seconds
  Minimum ice thickness for automatic dispensing                    3 mm
  Minimum time between automatic dispenses           More than 6 seconds

The Arduino firmware independently limits a dispense request to 5,000
ms. The gate is commanded open at approximately 90° and then closed at
0°.

The 15 g/s flow rate is a demo calibration value in the supplied code.
**Measure the actual salt mass released over repeated timed openings and
calibrate this value before interpreting gate duration as a reliable
physical dose.**

## Safety and current limitations

-   This is a prototype and should be tested on a controlled test
    surface, not deployed on public roads.
-   Do not use model output as a certified or authoritative
    road-treatment recommendation.
-   Synthetic training labels are generated from a manually chosen
    formula; they are not field measurements.
-   Temperature and humidity are manually supplied through the dashboard
    in the current implementation.
-   The salt flow rate must be physically calibrated.
-   Ultrasonic measurements depend on sensor mounting, surface geometry,
    reflections, and the chosen baseline.
-   The current dose conversion and gate timing do not by themselves
    verify how much salt actually leaves the dispenser.
-   The manual dispense endpoint uses a 1,000 ms fallback if the
    calculated gate duration is zero; use care when testing this
    endpoint.
-   The Python and Arduino maximum-open-time settings should remain
    synchronized.
